# What tests/Wiring.lean cannot tell from the code: which definitions a
# law states running code against, what is assumed, which mirrors are
# proven equal to running code, and what would make each model real.
# One note a line: a kind, a name, and text. tests/Wiring.lean fails on
# a note that is stale or wrong.
#
#   entry NAME           an entry point besides `main` and the runner: an
#                        `@[export]` whose symbol a shipping platform's
#                        source names
#   spec NAME TEXT       a specification laws state running code against.
#                        Not a subject (it must not run); of what it names,
#                        what runs is.
#   assume NAME TEXT     an assumption: a hypothesis the laws take, or a
#                        model of something the running code is generic
#                        over (the store, the cryptography). Not a subject.
#                        TEXT `= OTHER` makes NAME part of OTHER's.
#   bridge MIRROR LAW    LAW, audited, concludes that running code equals
#                        MIRROR, so laws about MIRROR are about it
#   todo NAME TEXT       what would make the laws about NAME, which does
#                        not run, about running code (one sentence). The
#                        README's rows follow this file's order; `= OTHER`
#                        puts NAME in OTHER's row. It must not run, and a
#                        law must wait on it.
#   holds NAME TEXT      a premise laws take (an invariant) that the
#                        running node keeps only as TEXT says; listed with
#                        the assumptions, and seen through like any premise
#   world NAME TEXT      NAME is a World's network, transport or harness:
#                        a law that misses only these, and whose node code
#                        is the running `Engine.Sync.Node`'s, is a World law
#                        (not wired, not counted as a model). It must not
#                        run, and a law must miss it. `= OTHER` as for todo.
#   control NAME TEXT    NAME is a mutant, a negative control meant never to
#                        run: a law that names it proves the mutant breaks
#                        its law, and is counted apart (never wired, never
#                        a todo, out of the lead's count). It must not run,
#                        and a law must name it.
#   instrument NAME LAW  NAME is what code under test runs in to be
#                        measured (the cost meter); LAW, audited, is an
#                        equation naming it that erases it to the plain
#                        run. Left out of subjects, like an assumption.
#   weak NAME TEXT       NAME must not be reached from any entry point
#                        (main, the runner, a shipping @[export]): a
#                        secret made from it would be guessable
#   door NAME DOOR       among what the entry points reach, only DOOR (one
#                        line per door) may run NAME: every secret the
#                        app makes from the OS's randomness, one place
#   copy NAME CODE TEXT  NAME restates running CODE instead of naming it:
#                        a law (a model until it names CODE) or a
#                        definition (a todo, until CODE calls it)
#   subject LAW NAMES    LAW's subject is NAMES (its statement must name
#                        each), where the heuristic takes too much
#   wired LAW            LAW must be wired
