# Execution progress: target and current boundary

The target is now two separate results, without a quiescence requirement:

1. Bounds enforced by the running app under arbitrary input: bounded admitted
   queues and work, bounded service of local work and each admitted peer, and
   waits that complete or are cancelled. UI work has priority, with a reserved
   minimum share for sync.
2. Per-operation delivery and validation between honest connected peers under
   continuing execution and fair-loss transport. A message retried indefinitely
   must eventually be delivered. New posting may continue indefinitely.

**Neither complete result is proved yet.** In particular, a selector's bounded
service theorem counts completed turns. It does not prove that an arbitrary
SQLite/native call completes, or that a separately scheduled display worker
runs within a fixed number of networking turns.

## Completed runtime connection

[Loop.turn](../engine/wire/Loop.lean) is now the polling, dispatch and timer core
called by the native TCP runner. [Node.step](../engine/wire/Loop.lean) dispatches the actual
write, frame, tick and close handlers, including closes generated by applying
effects. The native backend retains real SQLite, sockets and connection hooks.

[LoopLaws](../engine/wire/LoopLaws.lean) proves preservation of the observed
input, scheduler preference and actual timer decision. The `Loop.Step`
relation evaluates that same function with explicit backend state. It does
not assert native-backend refinement or termination of external calls.
The first extraction preserved scheduling. The subsequent
[priority selector](../engine/wire/Priority.lean) restores local preference in
three of four turns and guarantees one network-preferred turn in four, with
immediate fallback. [PriorityLaws](../engine/wire/PriorityLaws.lean) proves
`2 * (p + 1)` and `4 * (p + 1)` bounds for admitted local/network entries with
`p` predecessors, even while both producers keep appending. Timer checks
remain after every completed turn. Native branch/order checks and the old
write-starvation and deferred-dial controls run in `test:join-fair`; an
always-network-first mutation must also fail the unchanged loop laws.

[StorageEffects](../ops/connection/StorageEffects.lean) proves that every
actual `Node.step`, with production hooks and advancing entropy, preserves
shared bytes, reachability and settlement. This includes reaction writes and
both courier and session purges. The native storage fixture has 24 checks.
The [stronger drain law](../ops/sync/StoreEvolution.lean) no longer needs
collision-free history to prove termination; its budget still grows with
history, so it is not a fixed per-turn bound.

[WriteAdmission](../ops/app/WriteAdmission.lean), called by `App.writeAll`,
limits new admitted pending work to 8,192 ops and 128 MiB and requires each op
to fit the standard encrypted frame alone. Refusal precedes optimistic
display and queueing, preserves Send's draft and reports a reason. Three
kernel bounds, ten real-app/SQLite checks and three mutation controls cover
this path. Other submission/recovery paths remain in the capacity audit.

[WriteProgress](../ops/connection/WriteProgress.lean) proves that the complete
local-write handler commits compatible shared input bytes before returning,
including all subsequent reactions and purges. This is an exact readable
store result, with same-ID representation compatibility stated explicitly;
it does not prove native SQLite completion or display-worker scheduling.
`host:net-join` now also measures actual Send, SQLite read-back and the exact
current committed bitmap during a continuing TCP workload. Its finite
regression bounds are 64 app frames and 1,500 ms; the checked 3:1 run completed
all four reads in one frame and all four paints in three frames, in 27–48 ms.
These measured stage bounds are not universal theorems.

[Sweep](../ops/sync/Sweep.lean) adds one indexed catalog read per session tick,
with a fixed high-water mark during each pass. Its cursor persists under an
authenticated peer key, so replacing a session does not restart progress.
[SweepLaws](../ops/sync/SweepLaws.lean) proves repeated emission of a retained,
authorized, fitting row under recurring output reservation, despite arbitrary
later inserts and intervening zero-room stalls. `Sweep.FairLoss` names the
external semantic-payload delivery contract; fresh encryption nonces need
not reproduce identical ciphertext. [SweepRun](../ops/sync/SweepRun.lean)
exposes the exact runtime cursor inputs. [CatalogEvolution](../ops/connection/CatalogEvolution.lean)
derives stable Held catalog positions through every actual handler and
arbitrary execution suffix, including local-secret purge.

`test:catalog-retry` passes 14 checks with signed ops and SQLite: all round
controls lost, the first two target payloads lost, a new post on every tick,
and 86 replacement sessions. The target still arrives and validates. The
disabled-retry mutant compiles and fails delivery; restored code passes.
This closes those concrete failures, not the internal reservation obligation.

## Obstructions found by the stronger target

| Obligation | Concrete remaining issue |
|---|---|
| Per-peer service | Readers compete to enqueue into one shared event channel. A bound for an already admitted event does not bound admission by each peer. |
| Wait cancellation | A writer blocked in native send cannot observe its stop flag. The slot remains occupied until native send returns; the stall clock alone does not prove cancellation. |
| Bounded iteration work | Store draining has a finite history-dependent budget, not a fixed configuration bound. Connection hooks can traverse all matching rows. |
| Bounded memory | The sync index, snapshots, retired-session routing/tombstone history and some app recovery queues grow with history. |
| Fair-loss progress | Ordinary traffic can refill the socket before every tick, leaving zero retry room forever. A separate output reservation still needs implementation and proof. Seventeen fitting ~1 MB hot responses can also overflow the 16 MiB socket cap and discard a queued retry. |
| Write-to-display bound | Selection, commit, reader refresh and presentation are separate stages. Worker delays are not bounded by the selector. Even with progressing workers, recurring reaction updates can replace a row's paint ticket before every completed bitmap is published; finishing a still-valid first paint needs protection from this churn. |

The current work addresses these in the running code. A successful finite
test or a new component lemma does not close the corresponding whole-app row.

## Necessary statement boundaries

- **Shared and authorized data:** local signing keys and session secrets must
  never be replicated. A revoked peer must not receive later private data.
  “Every op” therefore means persistently retained shared ops that the peer is
  authorized to receive, within the configured history window.
- **Valid, complete input for application:** an invalid signature must not
  become a valid message. A valid dependent op cannot settle as valid without
  its finite prerequisite closure. Replication and successful validation are
  separate claims.
- **Execution and storage progress:** a process that never runs cannot make
  progress. Scheduling one thread forever can still starve another required
  reader, writer or native event-loop thread. Scheduling alone cannot make a
  permanently blocked disk operation finish. Native operations need proved
  cancellation or an explicit completion contract; these are not currently
  discharged by Lean.
- **Transport:** an adversary that drops every copy defeats delivery. Fair-loss
  is sufficient only after the app is proved to retry each relevant payload
  indefinitely, including across its own queue limits and session changes.
- **Supported bytes and correct implementations:** crypto, framing, persistent
  storage and native code must implement the stated semantics. Finite tests do
  not prove those universal contracts. Oversized historical or imported ops
  require rejection or fragmentation; a frame limit is not delivery fairness.
- **Quantifier:** without quiescence the intended result is
  `for every eligible op, eventually both peers retain and settle it`.
  It is not `eventually their entire changing stores are equal at every time`.

The pending universal theorem must name these domains and any remaining
environment contracts in Lean. Application scheduling fairness is to be
derived from the actual selector, not supplied as a liveness premise.

## Reproduce

All Lean/Lake builds for this work run beneath:

```sh
flock /mnt/storage/holmes-tmp/lean-quiet-contracts-build.lock \
  systemd-run --user --scope -p MemoryMax=48G -p MemorySwapMax=0 \
  env QUIET_BUILD_LOCK_HELD=1 ELAN_HOME=/mnt/storage/elan TMPDIR=/mnt/storage/holmes-tmp \
  PATH=/mnt/storage/elan/bin:$PATH mise run test:join-fair
```

The same scope must surround other build/test tasks, including mutation
scripts that launch Lean themselves. Logs and scratch builds stay on
`/mnt/storage`. Hosted CI activation still needs the previously reported
GitHub workflow credential; the reviewed workflow remains inactive.
